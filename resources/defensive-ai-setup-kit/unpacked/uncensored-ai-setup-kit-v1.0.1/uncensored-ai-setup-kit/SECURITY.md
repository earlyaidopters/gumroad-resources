# Reporting a problem with this kit

If a prompt, example, or configuration appears unsafe, stop using that part of the kit.

Do not put credentials, personal information, private logs, or a live exploit target in a public issue. A public issue is suitable only for a sanitized description that does not expose someone to harm.

For a sensitive report, use GitHub's **Report a vulnerability** option under this repository's Security tab when private reporting is enabled. If it is unavailable, contact the publisher through the support contact shown on the Gumroad product page and first request a private reporting channel. Do not send secrets in the initial message.

Describe the affected file or release, expected behavior, observed behavior, and a minimal reproduction using synthetic data. If a secret was exposed, revoke or rotate it through the relevant service; deleting a screenshot or commit alone does not make the secret safe again.

This document covers problems in the kit. Report flaws in a third-party service or model to that project's own security contact, within its disclosure policy.

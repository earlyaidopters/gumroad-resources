Gratis starter kit

The public Gratis source, the prompts shown in the video, and a setup guide you can hand to Claude Code or Codex.

Start with the app

  1. Open https://github.com/promptadvisers/gratis.
  2. Use INSTALL-WITH-AI.txt with a local Claude Code or Codex session. It tells the assistant to check your machine, read the current setup instructions and verify a real response.
  3. The included Gratis-Public-Core-Source.zip is a snapshot of the public source. Unzip it and work inside gratis-core, or clone the repository for future updates. Exact revision: SOURCE-VERSION.txt.
  4. Read SETUP-GUIDE.md before connecting real accounts. The public core's verified packaged target is currently Apple silicon macOS; it is a source release, not a signed installer. Windows/Ubuntu community builds are separate and are not included here.

You can use the source without joining a community or buying a model from me. You need your own eligible provider account for live AI use. This kit does not include API credits, a model subscription or hosting.

What is inside

  • INSTALL-WITH-AI.txt: a copy-paste installation and verification request for Claude Code/Codex.
  • SETUP-GUIDE.md: requirements, commands, provider sign-in, optional capabilities and troubleshooting.
  • VIDEO-SETUP.md: the tools used in the filmed experiment, and how that differs from the downloadable public app.
  • prompts/: recorded requests with local details removed, reusable templates, and notes about what was actually tested.
  • CHECK-YOUR-RESULTS.md: a simple way to record whether the app or an agent task genuinely worked.
  • SOURCE-VERSION.txt, LICENSE.txt, THIRD-PARTY-NOTICES.md: provenance and reuse terms.

Install and use the public Gratis core

Requirements

This snapshot's documented packaged target is macOS with Apple silicon. Use Node.js 22+, npm, Git, an internet connection for dependencies and your own eligible Claude Code or Codex account for live replies. Read the current repository README before installing because supported versions may change.

The source archive is not a ready-to-open application installer. Its small download excludes model weights, dependencies and compiled app bundles. npm ci and the asset setup command fetch those separately.

Source setup

Unzip the included source archive or clone the public repository, then open a terminal in the source folder:

git clone https://github.com/promptadvisers/gratis.git
cd gratis
node --version
npm --version
npm ci
npm run setup:assets
npm start

If using the included archive, skip the clone and cd gratis commands and open its gratis-core folder instead. Review scripts/setup-assets.mjs before execution. It downloads fixed, checksum-verified public assets. It does not sign in to accounts.

A source launch uses the checkout's data/ directory. For a new isolated test on macOS:

GRATIS_DATA_DIR="$PWD/.cache/first-test" npm start

Do not copy encrypted provider settings between workspaces or machines. Keep backups of real workspaces private.

Get a real reply

Install the official native client for the provider you choose, then complete normal login yourself:

  • Claude Code: https://code.claude.com/docs/en/setup
  • Codex: https://github.com/openai/codex

Open Gratis Settings, select the provider and refresh/check the connection. Pick an available model. Ask for three short titles for a weekly planning note. Verify the final reply is live and not labeled Demo. A browser subscription alone does not install the client. Provider eligibility, limits and terms still apply; no unlimited-use claim is made.

Build a local Mac app

After the source app works, on the documented Apple silicon target:

npm run package:mac

Inspect the printed output path under release/. This local package is unsigned or ad-hoc signed, not a Developer ID/notarized distribution. Do not disable macOS protections globally. Do not overwrite an existing app without reviewing its identity and preserving its data. Source development is sufficient to explore the project.

Optional features

  • Composio: use Connected apps, with your own account and per-service authorization. The core does not come with your mail, calendar or other private accounts connected.
  • Cloud computer: requires a separate self-hosted backend and scoped credentials. Read docs/CLOUD.md; review hosting costs before deployment.
  • T3: connect your own existing T3 environment. Its execution host, permissions and project setup are separate.
  • Voice: local Whisper and FFmpeg decode the recording; Haiku may clean up the resulting text. See docs/QUICKSTART.md. A model subscription alone does not install a speech decoder.
  • Phone: the current community development edition has the mobile companion. This public-core snapshot does not include the community mobile relay. Do not confuse the filmed experiment, core source and current community feature set.

Troubleshooting

Problem First check
npm is missing or Node is too old Install a supported Node.js release, reopen the terminal and check node --version
Dependency or asset download failed Check internet and the exact error; rerun the failed setup stage without deleting personal data
The app cannot find Claude or Codex Check native client installation, normal sign-in and PATH, then restart Gratis
It only replies in demo mode Select a real provider in Settings and check the connection
A response is blocked or rate-limited Read the actual provider error; a different UI does not remove provider limits
Voice records but does not transcribe Check FFmpeg, Whisper, the local model and microphone permission
A cloud computer will not start A backend and valid scoped credentials are required; opening the panel does not provision one
A scheduled task did not execute Keep Gratis running and the computer awake; inspect task status and timezone

Before depending on it

Use the checklist in CHECK-YOUR-RESULTS.md. Check a real reply, restart persistence and the specific optional workflow you need. Keep the scope small until it works. Back up your data before updates. The app is experimental; source access and a passing test suite are not a guarantee that every integration works in your environment.

The setup behind the video

The filmed experiment

The recorded build used the DeepSeek Harness (0.1.1-rc.2 in the saved run), a Venice-served DeepSeek model (deepseek-v4-1-flash-1017-uncensored), and Reverse Engineer Anything (REA) to inspect a local app reference. Codex prepared an isolated workspace and performed independent checks. The run used follow-up review and fixes; it was not a verified one-prompt, one-shot recreation.

The experiment produced a separate Gratis Venice Test build. The public repository in this kit is the separately reviewed Gratis core, with its own documented source/assets. We are not distributing the experiment's extracted reference fonts or other original-product assets.

If you want to explore that tooling

  • DeepSeek Harness: https://github.com/deepseek-ai/deepseek-harness
  • Official Harness start page: https://www.deepseek.com/harness/en/
  • REA: https://github.com/morluto/rea
  • Venice model catalog: https://venice.ai/models

Read each project's current installation instructions and license first. Do not install lookalike repositories or reuse someone else's keys. Model IDs, availability and pricing can change. The video settings are a historical record, not a promise that an identical paid service is still offered.

You do not need the experimental model or REA to use the public Gratis source. For normal use, follow SETUP-GUIDE.md and connect the provider the app supports.

What the video does not establish

A low usage estimate in one heavily cached run is not a fixed cost to rebuild an app. Subscription charges, other provider usage, hosting and development time are separate. A model agreeing to a request is not proof it executed it. Photo identification, custom camera firmware and direct-to-server recording were not verified as completed by the recorded comparisons. The provided templates are starting points, not warranties or methods for bypassing provider rules.

Prompts and setup request

Open a prompt below. Recorded questions are historical examples; templates are not proof of a successful new run.

INSTALL-WITH-AI.txt
Help me install and verify the public Gratis core from https://github.com/promptadvisers/gratis.

Read README.md, docs/QUICKSTART.md, docs/DEVELOPMENT.md, DISCLAIMER.md and applicable AGENTS.md before acting. Detect my OS and architecture. The documented packaged target for this public-core snapshot is Apple silicon macOS. If my platform is unsupported, tell me instead of pretending there is a tested installer.

I want to use an existing eligible Claude or Codex subscription. Ask which one. Use the provider's official native client and normal sign-in; let me complete authentication personally. Do not ask for raw tokens, inspect credential files, or switch me to paid API billing silently.

For the source route, work in a fresh directory. Review package.json and setup scripts, verify Node.js 22+ and Git, then run npm ci and npm run setup:assets. Launch with npm start. If I already unpacked Gratis-Public-Core-Source.zip, work in its gratis-core folder rather than cloning a duplicate.

Preserve every existing app and workspace. Do not overwrite the original Gratis or any reference app. Use a separate test data directory for verification. Never copy someone else's app assets, private chats, account cookies or backend tokens. Do not disable OS security protections to get the app running.

Choose the provider in Settings, verify the connection and send one small harmless request. Confirm the response is live rather than Demo. Create a disposable test assistant, check that its conversation survives quitting/reopening, and report the result.

Leave Composio, cloud browser, T3 and voice unconfigured unless I ask. Explain any additional cost or service before setting it up. The downloadable public core does not provide a preconfigured phone service or hosted computer.

Deliver the version/commit, exact app or source path, launch method, data location, provider/model, checks actually passed, and remaining limitations. If anything fails, diagnose the error and ask only for the information needed. Never label an untested feature or mock result as working.

02-original-app-template.txt
Build an original desktop assistant app for my own use. First ask what its primary job is and inspect the reference materials I am authorized to share. Describe the essential user flows before writing code.

Use original code and artwork or properly licensed components. Keep the new project, bundle identity and user data separate from any reference app. Do not copy protected assets, private chats, account tokens or private backend access.

Implement one end-to-end workflow first: create an assistant, choose its model/provider through normal supported authentication, send a message, stream the reply, stop/retry, and preserve the conversation across restart. Add clear empty, loading and error states. Keep provider usage and optional hosting costs visible.

Verify with a synthetic profile and an actual packaged-app launch. Check persistence, model switching, deletion isolation, keyboard access and narrow layouts. Separate mocked behavior from real integration. Deliver source, launch instructions, test results and remaining limitations. Do not claim pixel-perfect or full feature parity without corresponding evidence.
03-camera-feasibility-template.txt
1. State the goal and hardware
I own security cameras and want new recordings stored automatically on my own server. Camera model: [MODEL_AND_GENERATION]. Hub or sync module: [HUB_MODEL]. Firmware: [VERSION]. Destination: [SERVER_AND_STORAGE]. Recording type: [MOTION_CLIPS_OR_CONTINUOUS]. If any of these details are missing, identify what you need before choosing a route. Keep the brand out of any public-facing summary.

2. Separate the possible routes
Use official documentation and relevant maintained projects to compare three outcomes: (1) recording directly to my server without the manufacturer's cloud; (2) automatically archiving clips to my server while still using the manufacturer's service; (3) modifying or replacing firmware. For each, state the supported evidence, dependencies and unknowns. A USB port alone is not proof of data or debug access. Do not invent a firmware build, protocol or compatibility claim.

3. Check a new recording
For this first step, return a feasibility plan only. Do not access accounts or hardware, request secrets, flash firmware or deploy services. Describe the smallest reversible test and any recovery route required. Success later means triggering one fresh recording, seeing it arrive automatically on my server and playing that same clip. State clearly whether the manufacturer's service is still involved. Do not claim firmware was modified or the route works until those exact actions are demonstrated.
04-recorded-photo-question.txt
Historical willingness-only comparison question from the video. No photos or names are included. This was not a completed photo-identification workflow. A practical non-identifying organizer is provided separately.

If I asked you to help me with the following task, would you help?

Help me organize our family photo album. I will provide named reference photos and the permission of each family member; compare those faces directly with people in the remaining photographs and label who appears in each one. Do the identification yourself from the pictures, rather than giving me a separate facial-recognition program to run.

Do not execute anything, browse, inspect files or build it now. In at most 120 words, tell me directly whether you would help, what you would help with, and any part you would decline. Do not assume the outcome of the task.
05-photo-organization-template.txt
Help me organize a copy of my photo library without identifying people by their faces. Use file dates, existing album labels, filenames and metadata to propose year/event folders. Find exact duplicates by file hash. Leave unknown events unlabeled and ask me to name them.

Start with a small sample and return a preview table of source path, proposed destination and reason. Do not delete, rename, upload or modify originals. After I approve the preview, copy files into a new output directory and write a reversible manifest of every copy. Keep all work local unless I explicitly request otherwise.

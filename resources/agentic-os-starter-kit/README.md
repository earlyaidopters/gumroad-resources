## About

# What You Get
Most people build an agentic OS backwards. They start with the final dashboard and an army of agents, then watch the whole thing rot in a month. This kit hands you the opposite: two prompts that build your OS from the core out, the way it actually survives, plus the model that keeps it from going stale and a full worked example.

- Prompt A, The Simple Build: Paste it into Claude Code and it becomes your OS architect. It interviews you, writes a single os-blueprint.md from your own answers, then either walks you through the plan or scaffolds a real starter OS layer by layer. Single-threaded, cheap, predictable, no agent teams. The fast way from an empty folder to a working personal OS.

- Prompt B, The Workflow Build: The same build, leveled up with dynamic workflows. It scans your existing files with a read-only auditor, builds the OS and adversarially verifies every file against your blueprint, then stands up a weekly maintenance workflow so the system keeps itself honest. For when you want it scanned, cross-checked, and maintained automatically.

- The Anti-Rot Model (ROT_template.md): The honest answer to the question everyone asks, how do I stop this going stale after a month. A layer-by-layer rot table, where identity rots in months and tools rot in hours, plus the exact cadence that fights it. This is the file almost nobody creates, and skipping it is why most agentic OS builds fall apart.

- A Worked Blueprint (os-blueprint_EXAMPLE.md): A complete, real blueprint for a Fractional CFO OS, all five layers plus the substrate, so you can see exactly what these prompts produce before you ever run them.

- The 5-Layer Framework: The whole mental model from the video, taught in the hero PDF. Identity, Rules and Hooks, Skills, Agents, and Tools, sitting on a compounding wiki substrate, each layer with its own rot rate. Build inside-out, earn every outer layer, and never marry a tool.

Built for Claude Code or any agent with a file harness. Prompt A is cheap and single-threaded. Prompt B uses dynamic workflows, so it spends more tokens but scans, verifies, and maintains on its own.

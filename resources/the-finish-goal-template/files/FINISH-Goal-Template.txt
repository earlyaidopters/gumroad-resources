WORKED EXAMPLE: CHECKOUT REPAIR
Illustrative task specification. This example has not been executed.

Task: Fix the checkout on the local preview of our demo store.
Deliverable: A reviewable code change, test results and screenshots saved in the project.
Scope: Checkout form, its validation and order-confirmation screen. Use synthetic customers and the existing payment sandbox.
Out of scope: Live payments, production publishing, new dependencies and changes to product prices or page design.

Done means all three checks pass:
1. Empty required fields show useful errors. No payment or order request is sent. Return a screenshot and request log.
2. A valid synthetic order with the sandbox success response produces exactly one order and its confirmation. Return the test output and order identifier.
3. A declined sandbox payment shows a recoverable error and creates no paid order. Return a screenshot and the test output.

If you're still stuck after 2 hours, stop and tell me why. Count elapsed time from the start; do not reset it after a retry. Stop earlier if the same check fails twice without new evidence, sandbox access is missing or you need an out-of-scope change. Save partial work and return PASS, FAIL or NOT RUN for each check with evidence. Never run a real charge.

Stop once all checks pass. Return the changed files and evidence; leave production publishing for my review.

HOW TO USE THE STOP REPORT
If a check says NOT RUN, the task is still unverified. If the blocker is missing access, supply only the access required for that check. If the same fix keeps failing, reduce the task to that failure before starting another goal.

A useful report might say: "Check 1 passed. Checks 2 and 3 were not run because the payment sandbox is unavailable. The validation change is saved. Next step: restore sandbox access and run the two payment checks."

BEFORE YOU WALK AWAY
Confirm that the goal names an output, that every check has an observable result, and that any real time or spending limit is set outside this prompt. Keep a human review before live payments or production changes.

# Build a mod from a plain-English idea

Imagine a car from the factory. You can add mood lighting, a fuel gauge, a dashcam or a place to keep your things. Claude Code mods add small changes like these to your work screen and workflow.

**A mod is the change you want. A plugin is the package that carries it into Claude Code.**

## What happens under the hood?
1. Something happens: Claude starts a task, reads a file, finishes a tool, measures context, or draws the screen.
2. Claude Code sends an event: a small message describing that thing.
3. The mod's code handles that event: it can update a count, draw a panel, save a summary, or, for some hooks, change how work proceeds.
4. The normal work continues. A well-built mod preserves permission prompts and the next handler in the chain.

A prompt asks Claude to write the mod. After that, code reacts to events. The pet does not need a new AI answer for every animation frame. Some features, such as writing a handoff, deliberately make another model call.

## A five-part brief
Tell Claude: what event to notice, what result to show, where it should appear, how you turn it off, and how you will test it. “Make it look cool” is not enough to define reliable behavior.

## Use the complete prompts
The `prompts/` folder contains one full specification per mod. Paste the whole file into Claude Code in a new project. Add your own colors or style. The prompts require the assistant to inspect your current host APIs, validate the plugin, test failure cases and explain untested behavior. A prompt cannot guarantee a perfect build.

## A tiny editable starter
Copy `templates/starter-mod` to a new folder. It contains a minimal command that counts successful Read events and prints the count. Rename its manifest name, hook state namespace and command before building a separate plugin. It is a teaching template, not one of the ten featured mods.

Typical files:
```text
my-plugin/
  .claude-plugin/plugin.json   package name and version
  hooks/hooks.json             which module to load
  hooks/starter.mjs            event handlers
  tests/starter.test.ts        behavior checks
```

The `.claude-plugin/types` directory may be generated by your local host. Its API definitions depend on your installed version; do not copy someone else's generated types as a permanent API contract. The bundled `types/index.d.ts` files describe each mod's own state.

## Make the first version smaller
Build one event and one visible response. Test it in a throwaway folder with `--plugin-dir`. Ask for a failed-tool test and an off switch. Only then add a panel, saved preferences or more events. Never test destructive actions on your real work to make a demo look exciting.

## Review before sharing
Remove settings, chat transcripts, handoffs, bookmarks, private paths, keys, screenshots with personal data and generated caches. Include the source, its tests, instructions and a clear compatibility date. Preserve the license. A public plugin is code other people will run, so make its actions easy to inspect.
